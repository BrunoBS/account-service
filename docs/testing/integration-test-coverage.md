## Main coverage gaps

- Foundation Catalog is lowest by lines (78.12%) and branches (37.50%); uncovered code is concentrated in catalog code conversion and enum mapping paths.
- Feature Sharing is next lowest (75.87% lines, 34.50% branches), especially `ResourceSharingValidator`, `SharingReferenceGuard`, participant status/query logic and external resource reference paths.
- Core Environment remains at 87.64% lines and 61.86% branches; its topology/type validators, finder, query service and lifecycle operations have many unvisited decisions.
- Feature Dynamic Bundle, Onboarding, Parameter, Segmentation and Service Context all remain below 95% lines and branches. Their principal gaps are validation alternatives, normalization branches, filtering combinations and lifecycle/status transitions.
- Schema is at 94.58% lines and 64.38% branches. Dedicated workspace-path tests now exist, but the 95% branch target remains unmet.
- Coverage includes all production code in the reported modules, not only controller classes. Some branches are in helper/domain code with no public HTTP path. Do not claim those paths as HTTP-covered; use a separate non-unit integration mechanism only where a meaningful public contract exists.

## Validation limitations and next work

The 95% per-module targets are not achieved. The next pass should add domain-specific HTTP scenarios for reachable validator and lifecycle branches, beginning with Foundation Catalog, Sharing and Environment. Branches not reachable through a real application contract should be listed as non-HTTP-reachable rather than driven through artificial test-only hooks. Architecture tests must be run separately; their results are not included in JaCoCo integration coverage.
